# 保存时选择是否附带 Skill Lens

目标：B 用工具生成或修改 Skill 后，可选择把图解一并交给 C。C 解压包即可离线打开当前阅读页和原图，不依赖 B 的电脑或本工具安装路径。

## 创作者决定

在“生成/保存修改skill”的确认窗显示勾选项：

> 将 Skill Lens 视图一并打包（接收者可离线查看原图与上下文）

新包默认不勾选；已带合法受管理 Lens 的包显示当前已带状态并允许取消。勾选后导出图解资源和相对链接入口；未勾选导出普通 Skill。取消既有受管理 Lens 时，只移除工具生成的视图与导航，不删除未知自有文件。

## 随包结构

```text
SKILL.md
assets/skill-lens/
  index.html        当前阅读页，包含当前指令草稿
  origin.html       首次原图快照，最多保留一份
  graph.json        图结构和图对应的来源版本
  manifest.json     派生资源登记、哈希和图状态
```

SKILL.md 末尾的固定标记块提供相对链接。它只帮助人或 Agent 找到图，不要求执行、自动打开或读取完整 HTML，也不添加作者欢迎语。执行任务优先读取 Skill 指令及按需资料，HTML 供人查看。

## 原图与修改后的指令

视图记录的是生成时的声明流程。用户修改指令后，当前阅读页带有最新草稿，但图仍标为待重新解读；不能把旧图的来源指纹改成新包指纹来冒充已重读。

原图保留一次，当前阅读页随保存更新，不保存无限代嵌套历史。接收者可查看原图，也可把新包交给 Agent 重新阅读并生成新图。

## 防止重复自嵌

HTML 的核心源快照排除已验证的受管理 Lens 四文件。当前页如需再次导出原图，仅单层携带原图字节；原图叶子不再携带原图自身或任何先前当前页。

只有 manifest 结构、工具标识、登记路径和文件哈希均符合约定时，才按派生物处理。未知同名目录不能静默覆盖；篡改过的派生文件明确报错。来源指纹排除已验证派生视图及严格匹配的工具导航；核心业务文字仍参与校验，实际源文件字节哈希另保留。

这避免再导入时把旧 HTML 也读作业务正文，或每次保存都把整张旧图再次嵌入。正文、脚本、参考资料和手册原件仍按其正常规则保留。

## 最小验收

1. 不勾选时 ZIP 不新增受管理 Lens 或查看入口。
2. 勾选后 C 可从 SKILL.md 相对入口找到当前阅读页和原图。
3. 修改候选指令后，新 SKILL 内容准确、图状态为待重新解读，原手册不变。
4. 再导入、再次导出时原图保留、入口不重复、包体增长有界，视图不套娃。
5. 同内容目录/ZIP 的核心来源指纹一致，派生页面变化不伪装为业务内容变化；不支持的冲突明确拒绝。
